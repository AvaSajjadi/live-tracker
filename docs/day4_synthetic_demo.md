# Day 4 synthetic demo: sentence → rule → replay → answer → summary

> **SYNTHETIC DATA ONLY.** Every session in this demo starts with `SYNTHETIC_`. The scores come from
> `fake_scores` and the pose is generated by `replay_view.synthetic_pose`. They are not CalMS21
> recordings, not predictions of any model and not evidence about mouse behavior or welfare. The
> replay is a recorded session played back, **not a live camera**.

No API key, no network and no paid call are needed.

## 1. Install and run

Use the setup from the README (Python ≥ 3.10):

```
python -m venv .venv
.venv/bin/python -m pip install -e . -r requirements.txt   # Windows: .\.venv\Scripts\python.exe
```

The optional Claude extra (`pip install -e .[claude]`) is **not** needed for this demo. The Rules
page's default "Offline parser" does not use it.

Start the dashboard:

```
.venv/bin/python -m streamlit run app.py --server.address 127.0.0.1 --browser.gatherUsageStats false
```

- `--server.address 127.0.0.1` keeps the app local. On a wildcard address in headless mode,
  Streamlit also looks up the machine's public IP over the network.
- `--browser.gatherUsageStats false` turns off Streamlit's usage statistics.

Open http://127.0.0.1:8501.

Answers and journals are written to `outputs/replay/`, which is git-ignored. Set
`LIVE_TRACKER_REPLAY_DIR=<dir>` to use another directory, for example a fresh one per rehearsal.
Answers are final and persist across restarts, so a rehearsal in the same directory will find its
earlier answers.

## 2. Rules page: propose and confirm a rule

1. In the sidebar, open **Rules**.
2. Keep **Interpretation: Offline parser (default, no API key, no cost)**.
3. Enter exactly:

   ```
   Alert me when the mice attack for at least 2 seconds
   ```
4. Click **Propose rule**. Expected proposal **R1**:

   | field | value |
   |---|---|
   | behavior | attack |
   | minimum duration | 2.0 s |
   | alert mode | alert |
   | alert threshold | 0.8 |
   | ask threshold | 0.5 |

   The page warns that the thresholds are untuned defaults from `rules.py`, not values chosen on
   data.
5. Click **Confirm**. Expected: "Monitoring can start: 1 approved rule."

## 3. Replay page: the demo session

Open **Replay** from the sidebar. Use the in-app link: a browser reload starts a new Streamlit
session, and the rule would have to be confirmed again. Expected on arrival:
- the banner "Replay of a recorded session, not a live camera";
- the session **Demo session (alert, ask, short bout, lost tracking)**;
- a SYNTHETIC notice;
- both mice drawn.

**Controls:**
- **Play** and **Pause**, at 1×, 2× or 5× of recorded time.
- **⏮ Start**, **−1 s**, **−1 frame**, **+1 frame**, **+1 s**, and the **Frame** slider. Seeking
  stops playback.
- **End of session**: the state after the recording ended. This is the only view with the summary.

What appears in `SYNTHETIC_demo_01` (720 frames, 24 s, 30 fps) with R1:

| time (frame) | what you should see |
|---|---|
| 2.00 s (60) | an attack bout starts; nothing is shown yet (the rule needs 2 s) |
| **4.00 s (120)** | **ALERT** banner on this frame only; the events table gets row 1: onset 2.00 s, fired 4.00 s, closure "open (not ended yet)", confidence 0.93 (a model score) |
| 5.00 s (150) | row 1's closure becomes "5.00 s (below_threshold, last frame 149)" |
| 7.00 s (210) | the next bout starts (scores between ask 0.5 and alert 0.8) |
| **9.00 s (270)** | **ASK** banner; "Questions for you" shows the ask with **Confirm** / **Reject**; confidence 0.65 |
| 10.00 s (300) | the ask's closure becomes known |
| 12.0–13.5 s | a 1.5 s attack bout: **no event** (shorter than the 2 s rule) |
| **16.00–17.00 s (480–509)** | tracking lost: Tracking **LOST**, the gap note ("… not the mouse standing still"), a red border around the skeleton image, no solid keypoints. The high attack scores around it give no event: tracking loss ends a bout |
| **16.50 s (495)** | the tracking warning appears in **Tracking warnings**: missing_coordinates, mouse a, start 16.00 s, end "ongoing" |
| 17.00 s (510) | the warning's end becomes 17.00 s |
| 20–23 s | an investigation bout: no event under R1 (R1 is an attack rule) |

**Seeking back** hides everything that had not happened yet. Events, closures, warnings and answers
all reappear only at their frames.

## 4. Answer the ask

1. Go to a frame after 9.00 s, for example frame 280: **⏮ Start**, then **+1 s** nine times, then
   **+1 frame** ten times.
2. Under "Questions for you", click **Confirm** (or **Reject**).
3. Expected: "Answered: confirmed at frame 280", and the buttons disappear. Answers are written once
   to the journal; a different second answer is refused.
4. Seek back to frame 275. The ask is still visible but its answer is not: "An answer was given
   later in this replay; it is not shown before that point." Before frame 270 the ask itself is
   hidden.

## 5. Summary and export

Click **End of session**. Below the end-of-session view, **Session summary** shows:
- **SYNTHETIC test data**, the run ID, and "Source: SYNTHETIC";
- the recording: 720 replayed score rows, frames 0–719, 24.00 s at 30 fps, exact frame domain;
- the rule R1, with its description marked as supplied metadata;
- "Alerts: 1, asks: 1, logs: 0" and "1 confirmed, 0 rejected, 0 unanswered";
- the events table, with onset, firing, ending, duration (complete or observed), confidence (model
  score) and the answer ("confirmed (frame 280)");
- **Tracking warnings (separate from monitored events)**: 1, missing_coordinates, 16.00 s until
  17.00 s;
- the caveats.

**Download summary (Markdown)** and **Download summary (JSON)** export the same summary. It is built
only from this run's journal, the replayed frames and the separately labelled warning source. There
is no new detection, no statistics and no LLM wording.

Switching back to the demo session restores its position and its answer.

## 7. Known limitations

- **Synthetic only.** Real sessions are refused until H3 (Igor's test-session scores) and the
  held-out-session policy for H5. Thresholds are the untuned `rules.py` defaults.
- **Provisional tracking parts (pending Ava):** the skeleton edge list, the 0.15 keypoint score
  threshold, the warning flags (`low_conf` is added to Ava's), and warning storage. Warnings are
  shown and summarized separately; the journal accepts only alert, ask and log.
- **Synthetic pose is rough.** It is generated, roughly mouse-sized and not anatomically accurate. It
  exists to show keypoint statuses (tracked, low confidence, unreliable, missing).
- **Approximate refresh.** Playback refreshes about four times a second (`st.fragment(run_every=0.25)`).
  The frame shown can lag recorded time by up to one refresh, and playback rate matches recorded
  time (measured 1.00×, 2.00× and 4.99× in Chromium).
- **Tables need a screen.** `st.dataframe` draws its cells on a canvas, so screen readers and DOM
  text tools do not see table contents. The same facts are in the downloadable summary.
- **Answer positions are replay positions,** not recording timestamps. Answers recorded without a
  position show as "replay time unknown".
- **No locking across machines.** Journals use file locks (`fcntl.flock`) for concurrent tabs and
  processes on one machine. This is not tested on Windows or network filesystems.
